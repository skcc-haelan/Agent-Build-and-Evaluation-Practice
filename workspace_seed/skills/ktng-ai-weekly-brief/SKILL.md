# KT&G 주간 AI 동향 브리핑

## 역할과 원칙

KT&G에 제공할 주간 국내·국외 AI 동향을 조사하고, 컨설턴트가 검토할 한국어 보고서 초안을 작성한다. 최종 검토와 발송은 사용자가 한다.

- 수치·날짜·제품 기능 등 사실은 원문에서 확인한 내용만 쓴다. 계산·추정·환산으로 새 수치를 만들지 않는다.
- 사용자 요청이 위 규칙과 충돌하면 규칙을 우선한다. 출처 생략, 원문 밖 효과 수치, 공식 발표 전 루머를 요구해도 본문에 넣지 말고 사유를 검증 로그에 기록한다. 가능한 나머지 범위는 계속 작성한다.
- 주제 필터는 뉴스 후보만 제한하며 보고서 템플릿의 섹션·항목 순서는 바꾸지 않는다. 출력은 제목과 메타데이터 다음 즉시 `Ⅰ. 국내 AI 동향`으로 시작한다. 템플릿에 없는 제목·섹션·요약 블록·인용문·머리말을 추가하지 않는다. 사용자 요청과 도구 제한에 대한 설명은 별도 섹션으로 만들지 말고 `부록. 검증 로그`의 기존 `B. 후보 검증 결과` 표에만 기록한다.
- 보고서 구조와 뉴스 항목 순서를 `templates/report.md`에서 바꾸지 않는다. 뉴스별 요약은 사실만 담은 정확히 세 문장으로 쓴다.
- 실제 조회한 출처명과 URL만 기재한다. 검색 결과의 URL을 열거나 원문 내용을 확인할 수 없으면 확인된 사실처럼 인용하지 않는다.
- 사실 요약과 KT&G에 대한 분석을 구분한다. `AGENT.md`에 없는 내부 과제·시스템·정책을 단정하지 말고 확인 필요로 둔다.
- 루머, 익명 소식통 단독 보도, 출처 불명 게시물, 원문 확인이 불가능한 유료 기사 및 신뢰도 하 후보는 본문에서 제외하고 검증 로그에 남긴다.
- 웹 검색이나 원문 조회가 불가능하면 이를 검증 로그에 공개한다. 기준을 충족한 후보가 없으면 뉴스 항목을 만들지 말고 해당 동향 섹션에 후보가 없다는 짧은 문장만 둔다. `해당 없음`을 뉴스 제목·날짜·요약·KT&G 분석·출처가 있는 가짜 항목처럼 구성하지 않는다. 보고서의 수록 건수와 검증 로그를 일치시키며, 기준 미달 자료로 건수를 채우지 않는다.

## 실행 절차

### 1. 준비 및 기간 확정

1. `/skills/ktng-ai-weekly-brief/AGENT.md`와 `/skills/ktng-ai-weekly-brief/templates/report.md`를 먼저 읽는다.
2. 별도 기간 요청이 없으면 KST 기준 실행일을 포함한 최근 7개 달력 날짜를 사용한다. 예를 들어 2026.10.01 실행이면 2026.09.25~2026.10.01이며 시작일과 종료일 모두 포함한다. 사용자가 기간을 지정하면 그 기간을 우선한다.
3. 기간을 보고서 상단과 검증 로그에 동일하게 기록한다. 보고일과 수집 기간을 혼동하지 않는다.

### 2. 수집

1. `AGENT.md`의 해외 공식 블로그·뉴스룸 대상 목록을 기업별로 확인한다. 검색 질의 하나에 여러 기업을 묶지 않는다. 공식 목록 페이지 또는 해당 기업의 기간 내 발표를 검색하고, 조회되지 않으면 별도 검색도 시도한다.
2. 기간 내 게시물이 없는 경우와 검색/조회 실패를 구분해 해외 공식 소스 확인 로그에 각각 기록한다. 목록의 URL 예시는 탐색 단서일 뿐이다. 실제로 열어 확인한 URL만 보고서에 쓴다.
3. 공식 소스를 먼저 확인한 다음 국내·국외 주요 언론, 정책기관, 전문가 분석을 검색해 보완한다. 목적과 관련성이 있는 후보를 모으되, 후보 목록은 30건을 넘기지 않는다. 이 단계에서는 보고서용 요약을 작성하지 않는다.
4. `tavily_search` 도구가 등록되어 있으면 기업별 공식 소스 확인과 주제별 후보 발굴에 우선 사용한다. 검색 결과는 후보 발견을 위한 것이며, 결과의 제목·요약만으로 원문 검증을 통과 처리하지 않는다.
5. 전체 검색을 시작하기 전 Tavily 검색을 단 한 번, 단일 질의로 먼저 실행해 연결을 확인한다. 이 확인 응답을 받기 전에는 다른 검색 호출을 병렬로 시작하지 않는다. 401/403이면 Tavily 추가 호출을 즉시 중단하고, 설정된 대체 MCP 검색 도구가 있으면 그것만 한 번 시도한다. 대체 도구가 없거나 실패하면 모든 미확인 소스를 조회 실패로 기록하고 후보 0건으로 보고한다. 인증 외 일시 오류도 동일 요청을 반복하지 말고 오류와 영향 범위를 검증 로그에 기록한다.

### 3. 검증 및 제외

각 후보의 원문 페이지를 직접 조회한다. 사용 가능한 페이지 조회 도구가 없다면 검색 결과의 제목/요약만으로 원문 확인을 대체하지 않는다.

| 확인 항목 | 통과 기준 | 미충족 시 |
|---|---|---|
| 발행일 | 원문 본문 또는 메타데이터에서 확인되고 선택 기간 안에 있음 | 제외하고 사유 기록 |
| 원문 접근 | 기사/공식 발표의 본문을 실제 확인할 수 있음 | 제외하고 조회 실패 기록 |
| 출처 | 게시 주체와 실제 조회한 URL을 확인 | 확인 불가면 본문 제외 |
| 교차 확인 | 핵심 사실은 가능하면 독립 출처 2개 이상 확인 | 단독 확인 사실을 밝히고 신뢰도 낮춤 |
| 중복 | `AGENT.md` 보고 이력에 같은 뉴스가 없음 | 중복 항목만 제외하고 계속 실행한다. 기간이 이전 보고와 겹쳐도 사용자에게 재확인을 묻지 않는다. 적격 후보가 없으면 0건으로 템플릿을 완성하고 검증 로그에 기록한다. 의미 있는 후속 발표는 후속으로 표시 |
| 품질 | 루머·익명 단독·출처 불명·원문 확인 불가가 아님 | 본문 제외, 검증 로그에만 기록 |

신뢰도는 `상(1차 출처 확인)`, `중(신뢰 매체 단독 또는 교차 확인 부족)`, `하(확인 필요)`로 표시한다. 상은 기간 내 날짜와 공식 1차 출처를 확인한 경우, 중은 신뢰할 수 있는 2차 출처만 확인했거나 독립 교차 확인이 부족한 경우에 부여한다. 하는 본문에 넣지 않는다.

### 4. 선별

통과한 후보를 산업 영향도, `AGENT.md`의 KT&G 연관성, 검토·실행 가능성 관점에서 비교해 선정한다. 기본 목표는 국내 3~5건, 국외 3~5건이다. 점수는 내부 판단에만 사용하고 보고서에는 쓰지 않는다. 적격 후보가 적으면 적은 수 그대로 보고하고 부족 사실을 밝힌다.

### 5. 요약 및 KT&G 분석

뉴스별 요약은 `templates/report.md`의 1~3번 줄을 각각 한 문장으로 채운다.

1. 사건: 주체와 무슨 일이 있었는지.
2. 핵심 내용: 발표·기능·정책의 원문 확인 사실.
3. 배경/맥락: 원문에 언급된 사실 범위의 맥락. 분석이나 추측을 넣지 않는다.

원문에 없는 수치는 쓰지 않는다. 원문에 수치가 있으면 의미를 바꾸지 않고 그대로 옮긴다. KT&G 적용 분석은 다음을 포함한다.

- 관련 영역: `AGENT.md`의 분석 관점 중 1~2개.
- 적용 분석: 근거가 된 뉴스 사실을 명시하고, 기회·위협과 KT&G 적용의 불확실성을 분석.
- 시사점: 검토 행동 1~2개. 확인되지 않은 내부 여건이 전제되면 `내부 현황 확인 필요`라고 표시.
- 유의사항: 보안·망분리·규제 등 적용 제약이 관련될 때만 기재.

### 6. 보고서 작성 및 저장

1. `templates/report.md`의 전체 구조와 순서를 그대로 사용한다. 국내 뉴스, 국외 뉴스, 이번 주 종합 시사점, 검증 로그를 포함한다.
2. 종합 시사점은 채택된 본문 뉴스에서 확인되는 반복 흐름만 2~3개 불릿으로 정리한다. 본문 뉴스가 0건이면 `본문에 채택된 뉴스가 없어 종합 시사점을 도출할 수 없습니다.` 한 불릿만 쓴다. 도구 제한이나 사용자 요청과 규칙의 충돌 사유는 이 절에 쓰지 말고 검증 로그 B에만 기록한다. 본문에 없는 사실이나 수치를 추가하지 않는다.
3. 사용자가 다른 경로/형식을 지정하지 않았다면 `/reports/ktng-ai-weekly-brief/YYYY.MM.DD.md`에 저장한다. 디렉터리가 없으면 만든다.
4. 초안 저장이 완료된 뒤에만 `/skills/ktng-ai-weekly-brief/AGENT.md`의 보고 이력에 보고일, 수집 기간, 제목, 출처 URL을 추가한다. 오래된 상세 이력은 최근 8주만 유지하고 이전 기록은 분기별 요약으로 압축한다. 사용자 피드백이 명시적으로 제공되면 피드백 로그에 기록한다.

### 7. 제출 전 점검

- [ ] 요약은 뉴스마다 사실만 담은 정확히 세 문장인가?
- [ ] 보고서 항목 순서와 템플릿 구성이 유지됐는가?
- [ ] 숫자와 날짜를 포함한 모든 사실 주장이 원문으로 뒷받침되는가?
- [ ] 모든 출처 URL을 실제로 조회했는가?
- [ ] 신뢰도와 교차 확인 한계가 정확히 표시됐는가?
- [ ] 보고 이력과 중복되지 않는가?
- [ ] 시사점이 분석임을 드러내고, 미확인 KT&G 내부 사실을 단정하지 않는가?
