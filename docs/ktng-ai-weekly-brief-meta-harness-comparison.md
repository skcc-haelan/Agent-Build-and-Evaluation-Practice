# KT&G 주간 AI 브리핑 Agent 비교 보고서

- 실험일: 2026.10.01
- 대상: 기존 Agent(baseline) vs 개선 후보(v5, 최종 가드레일 변경은 v6)
- 실행: meta-harness 격리 실행, 각 질문 독립 실행, recursion limit 60, timeout 900초
- 판정 범위: 실행 완결성, 템플릿·기간·주제 처리, 규칙 우회 요청 대응

## 요약

기존 Agent는 6개 질문 중 4개에서 `GraphRecursionError`로 답변을 만들지 못했고, 기본 요청은 기존 보고 기간이 겹친다는 이유로 사용자에게 재확인을 물으며 검색·보고서 작성을 중단했다. 개선 후보는 질문별 보고서 파일을 생성했고, 지정 기간·주제 필터·수치 금지·출처 유지·루머 제외 규칙을 검증 로그에 표현했다.

다만 이 비교에서 Tavily 호출은 반복적으로 `401 Unauthorized`를 반환했다. 따라서 뉴스 사실의 정확성, 실제 출처 URL, 1차 출처 인용은 검증할 수 없었고 모든 최종 후보 보고서는 뉴스 0건이다. 테스트는 주로 실패 처리와 규칙 준수를 확인한 것이며, 정상 검색 상태의 브리핑 품질을 입증한 것은 아니다.

## 변경 가설

1. Skill에 기본값이 있으면 일반 시스템 프롬프트의 확인 질문보다 Skill의 절차를 우선한다.
2. 같은 인증 오류를 반복하지 않고 첫 단일 검색으로 연결을 확인한 뒤, 실패하면 검증 로그에 범위를 남기고 0건 보고서를 완성한다.
3. 사용자가 원문 밖 수치, 출처 생략, 공식 발표 전 루머를 요구해도 하드룰을 우선하고 나머지 요청을 계속 처리한다.
4. 중복 후보만 제외하고 기간 겹침을 이유로 실행을 중단하지 않는다.
5. 템플릿 밖 섹션·메모를 만들지 않는다. 검증 후보가 0건이면 가짜 뉴스 항목을 만들지 않고 각 동향 절에 후보 없음만 표시한다.

격리 실험에서 시스템 프롬프트 한 줄과 KT&G Skill의 절차·출력 규칙만 수정했다. 실험 과정에서 메모리 파일 변경은 meta-harness가 variant 안에서 복원했으며, 본체에는 승격하지 않았다.

## 실행 지표

Meta-harness의 `duration_s`, 도구 호출 및 아티팩트 요약 기준이다. 토큰 수는 재귀 오류 시 0으로 집계되므로 품질 비교 지표로 해석하지 않았다.

| # | Baseline 시간 / tool calls / 파일 | 후보 시간 / tool calls / 파일 |
|---|---|---|
| 1 | 24.9초 / 4 / 0 | 39.9초 / 13 / 2 |
| 2 | 148.1초 / 0 / 0 (오류) | 98.9초 / 10 / 3 |
| 3 | 57.8초 / 0 / 0 (오류) | 32.6초 / 9 / 2 |
| 4 | 88.0초 / 10 / 1 | 32.6초 / 9 / 2 |
| 5 | 156.1초 / 0 / 0 (오류) | 78.7초 / 7 / 1 |
| 6 | 106.0초 / 0 / 0 (오류) | 24.3초 / 8 / 1 |

표의 후보 수치는 q1~q3·q6은 v5 실행, q4·q5는 최종 zero-news 규칙을 포함한 v6 실행이다. v6는 v5에서 “후보가 0건일 때 가짜 뉴스 항목을 만들지 않는다”는 한 가지 Skill 규칙을 추가했다. 이 변경은 q4·q5에서 확인했다. v6의 q1 전면 재시험은 5분 이상 대기해 중단했으며, q1은 v5 결과로 판정했다.

## 품질 판정 및 한계

- 정상 요청 1~3: 기존 Agent는 q1 재확인으로 중단하고 q2·q3은 재귀 오류였다. 개선 후보는 정해진 기본값과 필터를 적용해 보고서 파일을 만들었다.
- 규칙 우회 요청 4~6: 개선 후보는 효과 수치를 만들지 않았고, 요청한 건수나 출처 생략을 따르지 않았으며, 미확인 루머를 본문에 넣지 않았다.
- 템플릿: v3·v4 중간 후보에서는 사용자 요청 설명을 별도 섹션이나 종합 시사점에 넣는 이탈이 있었다. v5·v6에서 설명을 검증 로그 B로 한정했고, q4·q5에서 재검증했다.
- 0건 보고: v5 q4는 `[해당 없음]`을 제목·요약·출처가 있는 뉴스처럼 만들었다. v6는 이 placeholder를 금지했고 q4 결과가 고정 구조를 따르는 것을 확인했다.
- 도구 한계: 각 v6 q4·q5 연결 확인은 Tavily 한 번으로 제한됐지만 401을 반환했다. 설정된 대체 MCP 검색 도구는 없었다. `.env`에 키가 존재한다는 점과 API 서비스에서 이를 유효하게 받아들이는지는 별개다.
- 정량 지표는 참고값이다. LLM 실행은 비결정적이며, q1 v6 재시험은 완료되지 않았다. 후보별 1회 실행만으로 성능의 재현성을 입증하지는 못했다.

## 결론

제한된 도구 환경에서도 완성된 검증 가능 초안을 반환하고, 재귀 오류를 줄이며, 규칙 충돌을 로그에 남기는 면에서 개선 후보가 기존 Agent보다 뚜렷하게 유용했다. 그러나 Tavily 401로 뉴스 수집과 출처 검증 품질을 시험하지 못했고, v6 q1 재시험도 완료되지 않아 정상 검색 상태의 우위는 아직 확인되지 않았다.

meta-harness 원칙에 따라 변경은 격리 variant에만 남겼으며 본체로 promote하지 않았다. v6 변경 diff를 검토한 뒤 승인되면 Skill과 시스템 프롬프트 변경을 반영할 수 있다. 정상 검색 품질까지 비교하려면 Tavily 인증을 복구한 뒤 여섯 질문을 baseline과 v6에 동일 조건으로 다시 실행해야 한다.
